# Phase 3 — Data Strategy

**SIH26059** · Zero-cost constraint (§7.4 of project definition) applies to every choice below.
All products selected are **free of charge** with open or free-use licenses; paid products are
excluded by rule. Access methods were verified against provider pages on 2026-09-05.

---

## 1. Selection criteria

Every candidate dataset is scored against:

1. **Zero cost** — free access, no subscription, no paid tier (hard rule).
2. **Scientific suitability** — variable relevance to sea-ice / iceberg / routing hazard.
3. **Resolution** — spatial and temporal resolution adequate for a ~25–100 km routing graph.
4. **Coverage** — full Southern Ocean / Antarctic coverage, including the Bharati–Maitri corridor.
5. **Historical length** — enough years to train + backtest (≥ 2 decades preferred where cheap).
6. **Accessibility** — scriptable download (CDS API, CMEMS API, HTTP/FTP); no manual clicking for the demo.
7. **Licensing** — open/free-use with simple attribution; must be publishable in a public repo and demo.
8. **Provenance** — documented source, version, units, CRS, quality flags.

## 3. Rationale and notes per domain

### 3.1 Sea-ice concentration (D1–D4)
- OSI-450 + OSI-430-b form one continuous, homogenized daily 25 km record (1978/79 → recent) —
  ideal for training a forecast model against a **persistence baseline** and for backtests.
- OSI SAF products ship `uncertainty` fields and status flags — this feeds the uncertainty
  engine (Phase 9) directly.
- OSI-408-a (10 km, AMSR2) adds higher-resolution NRT for the live demo map; NSIDC CDR v4 is the
  fallback record if OSI SAF access changes.
- CRS note: OSI SAF / NSIDC Antarctic grids use polar stereographic (EPSG:3412, 70°S standard
  parallel). All grid work happens in this CRS; lat/lon only at the API boundary.

### 3.2 Sea-ice drift (D5)
- OSI-405 provides 48-h motion vectors with per-vector uncertainty — used for sea-ice motion
  forecasts and for moving the ice edge during dynamic re-routing scenarios.
- Fallback: persist last observed drift (documented as persistence assumption).

### 3.3 Atmospheric forcing (D6, D7)
- ERA5 gives 10 m wind (u/v), 2 m temperature, mean sea-level pressure, SST — the primary
  forcing for iceberg advection (wind drag) and for the weather hazard layer.
- Wave parameters (significant wave height, mean direction/period) are included in ERA5 single
  levels — one download covers both.
- ERA5 is a reanalysis (frozen, complete, gap-free) — ideal for reproducible experiments and
  backtesting; it also powers the "persistence vs. ML" framing cleanly.

### 3.4 Ocean physics (D8, D9)
- GLORYS12 (1/12°, daily, 1993–present) provides surface and depth-resolved currents — the
  main advective driver for iceberg trajectory prediction (Phase 7).
- Fallback if CMEMS registration is delayed: ORAS5 via CDS, or ERA5 SST + climatological
  currents documented as such.

### 3.5 Icebergs (D10–D13, D16)
- **Real tracks:** BYU/NIC consolidated database (daily positions + size for hundreds of named
  bergs, ~1992–2017) is the training/validation ground truth for trajectory models; SCAR adds
  ship-based observations; NIC products cover recent events.
- **Demo tracks:** a well-documented giant berg (e.g., A-68A) gives a compelling "avoid the
  iceberg corridor" demo with real published data.
- **The gap we exploit (Phase 1 finding):** operational products (e.g., NAVAREA VI charts)
  report iceberg *presence per 1°×1° cell*; probabilistic *trajectory* hazard is our target.
- **Synthetic tracks (D16):** where labeled tracks are absent in our demo corridor, we generate
  physics-informed synthetic trajectories (GLORYS12 advection + wind + ice coupling + stochastic
  perturbations). They are **always labeled synthetic** and used for pipeline/validation
  development only, never presented as observations.

### 3.6 Ancillary (D14, D15)
- GEBCO bathymetry is optional realism for the map and for grounding-awareness context
  (iceberg draft vs. depth is a nice but deferred feature — see §8 scope note).
- Land mask is required to make the routing graph valid (no routes over Antarctica itself).

## 4. Demo scenario bundle (curated, offline-safe)

Locked corridor (SC-1): **Bharati (69.41°S, 76.19°E) → Maitri (69.77°S, 11.73°E)**.

- **Region box:** 55°S–75°S, 0°E–95°E (covers both stations, approach corridors, and sea-ice
  edge variability). Subset everything to this box at download time.
- **Primary time window:** austral summer **01 Dec 2019 – 15 Mar 2020** (typical resupply
  season; moderate ice year — good default demo).
- **Candidate secondary windows (for backtest / extreme scenarios):**
  - Dec 2022 – Mar 2023: record-low sea-ice summer (extreme scenario, re-routing demo).
  - Jul – Oct 2014: winter (harsh-conditions / no-route scenario tests).
- **Time step:** SIC/drift daily; ERA5 and waves 6-hourly; GLORYS12 daily means.
- **Vessel profile:** modeled research vessel (e.g., RRS *Sir David Attenborough*-class
  parameters, flagged as modeled per FR-6) — Phase 11.

### Estimated bundle size (subset, all variables)
| Product | Approx. size for 105-day window |
| ------- | ------------------------------- |
| OSI-450/430-b SIC | ~50–100 MB |
| OSI-405 drift | ~30–60 MB |
| ERA5 (8 vars, 6-hourly, box) | ~1–2 GB |
| GLORYS12 (u/v currents + SST, daily, box) | ~0.5–1.5 GB |
| Iceberg catalogs + tracks | < 50 MB |
| GEBCO tile (optional) | ~100–300 MB |
| **Total** | **~2–4 GB** (acceptable offline demo footprint; can trim to ~1 GB by using ERA5 daily means for the MVP) |

## 5. Storage layout & reproducibility

```
data/
  raw/            # downloaded products, NEVER committed (.gitignore)
    osi450/ osi430b/ osi405/ era5/ glorys12/ icebergs/ gebco/
  processed/      # aligned, subset, QC'd NetCDF/Parquet (NEVER committed; regenerable)
  scenarios/
    bharati_maitri_2019_20/   # curated bundle manifest (small metadata committed,
                              # heavy files gitignored)
  manifests/      # provenance JSON per dataset (source, version, res, units, CRS,
                  # missing-rate, license, preprocessing steps) — committed
configs/data_sources.yaml     # every product's URL/API id, variables, box, time window
scripts/data_fetch/           # fetch_era5.py, fetch_cmems.py, fetch_osisaf.py,
                              # fetch_icebergs.py, fetch_gebco.py, fetch_all.py
```

- All fetches are scripted; the curated scenario is reproducible with one command
  (`python scripts/data_fetch/fetch_all.py --scenario bharati_maitri_2019_20`).
- **Free registration only:** CDS (ERA5), CMEMS (GLORYS12), Earthdata (NSIDC fallback). Credentials
  are read from local environment variables — **never committed** (public repo).
- Data files are gitignored (NFR-7: heavy data downloaded by script, never committed); only
  manifests and metadata are committed.

## 7. Data quality & provenance requirements (maps to brief §23)

For every dataset, `data/manifests/*.json` records: source + version · timestamp coverage ·
spatial/temporal resolution · units · CRS · missing-data rate · quality flags · license ·
preprocessing steps. The UI data-status panel (OUT-7) exposes this, and missing/flagged data
**degrades confidence** rather than being silently filled (Phase 9).

| Product | Expected gaps / flags |
| ------- | --------------------- |
| OSI SAF SIC | missing near coast/land, weather-contamination flags; uncertainty field per cell |
| OSI-405 drift | sparse vectors; uncertainty per vector |
| ERA5 | gap-free reanalysis (no missing); frozen versions pin reproducibility |
| GLORYS12 | gap-free reanalysis; daily means mask sub-daily variability |
| BYU/NIC | tracks end ~2017; coarse weekly NIC segments; size estimates approximate |
| Synthetic tracks | by construction complete; labeled synthetic |

## 8. Scope control (what we deliberately exclude)

- **Paid anything:** commercial weather APIs, satellite tasking, PolarView/PolarView Next
  subscription services, paid cloud compute/hosting. Rejected by §7.4.
- **High-res SAR iceberg detection** (Sentinel-1 processing): scientifically valuable but heavy;
  classified COULD / NOT NOW — presence/trajectory products + synthetic tracks cover the MVP.
- **Iceberg draft vs. bathymetry grounding** (using GEBCO): elegant but deferred — note in
  `innovation-claims.md` as PROPOSED / NOT YET VALIDATED if ever claimed.
- **Live operational feeds:** out of scope by design (offline, curated scenarios; simulated
  real-time updates).
